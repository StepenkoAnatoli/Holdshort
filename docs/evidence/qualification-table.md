# Qualification table

Generated by `tools/qualification_table.py` from every calibration evidence folder `tools/check_calibration_evidence.py` accepts; do not edit it by hand. The regression gate runs `python3 tools/qualification_table.py --check`, which fails when this file differs from the generated table.

## What this table does not support

- No ordering between models: each cell is one observation under one run's protocol; no row ranks a model, an effort or a profile above another, however the counts compare.
- No cross-host comparison outside the shared pack's cells: a host pack is graded on that host's own code, so only cells graded on the shared subject pack compare across hosts.
- No claim about tiers it did not run: a cell speaks for the tier its run graded (runs 1-3 record no tier), and nothing here extends to a tier no run graded.
- No qualification: the host's rules qualify a profile for a category, from the runs this table lists; the table counts passes and names caveats, and grants nothing.

## How to read it

- One row per host, profile and category. Model, effort and config are as the run's protocol names them (`not named` when it names none); profiles carry the folders' labels, not a host adapter's profile ids. The pin case is the host category `pin-tests` (the host's rule 4) whatever a protocol labels it.
- A run column holds that run's grade for the cell: `PASS`, `PARTIAL`, `FAIL`, `UNGRADED`, `void`, or `-` when the run did not grade the profile on the category. A caveat is written after the grade in parentheses.
- Caveats: `2-prong, would fail` - a review PASS that holds only because the lens schema lacked a prong of the classification (it fails under the full definition); `unadjudicated` - a review PASS from a run with no adjudication record; `supplementary` - a cell graded in a supplementary run that replaced a void main-run cell; `void` - a void cell with no replacement; `judge not qualified` - a review PASS judged under the bootstrap limitation.
- `passes` counts the uncaveated PASSes of the row's graded cells: a PASS with any caveat is shown and not counted.
- `adjudication` names, per run, the schema version (`scores.json` `schema_version`) and the prongs the review grade rests on; `none` means no adjudication record; pin and fix are graded mechanically.
