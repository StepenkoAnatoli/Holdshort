## What changed

- **K1, category on the task object** (`observations.py`). When the manifest names `cases.<case>.category`, the
  `pin`, `fix` and `gate` task objects (graded or ungraded) and `review-grade` carry `category`. When it does not,
  no key is written and the output is byte for byte what it was. A committed golden copy proves this:
  `tests/fixtures/calibration/golden-no-category/`, the pre-change builder's output on the fixture folder with every
  category removed.
- **K2, `cases.pin.mutants`** (`grade.sh`). A list of `{id, commit}`; anything else is refused. A duplicate id is
  refused. Each commit is rev-verified like the base and the accepted fix.
  - The pin grade swaps in each mutant's source after the base run, each swap with its own mtime step. It records
    `atMutants` and `redAtMutants: {id: bool}`.
  - PASS also needs every mutant red.
  - Without mutants the grade has the same keys, in the same order, as before.
  - `observations.py` copies `redAtMutants` into the pin task object.
- **K3, the `gate` case kind** (`grade.sh`, `run.template.js`, `observations.py`). `grade.sh MANIFEST gate CHECKOUT`
  passes the cell when all four of these hold:
  - `commands.gate` exits 0 (run with bash in the checkout; timeout `commands.timeout_seconds`, default 900, read
    as exit 124);
  - every `invariants` path's file set and blob ids equal the base's. The candidate side is `git hash-object` over
    the tracked and the untracked, not ignored files, as the checkout stands, committed or not;
  - every `required_paths` path exists;
  - the candidate committed.

  Both path checks are read before the command runs, so the command's side effects cannot mask the candidate's work.
  The grade carries `gateExit`, `invariantsIntact`, `requiredPresent` and `committed`. It refuses a missing
  `commands.gate`, a path list that is not a list, a path outside the checkout, an invariant the base does not hold,
  and a case the manifest lacks.
  - `run.template.js` builds gate items per profile next to pin and fix, with no grader agent. The prompt is the
    common preamble (opening, relayed-text reconciliation, checkout rules, commit command, honesty line) plus
    `TASK (category …): <instructions> Commit your work on your branch.` The schema is commits, summary, mistakes.
    The pin/fix/review prompts are byte-identical before and after the split, checked on the fixture config.
  - `observations.py` accepts `gate` as a fourth kind. It counts `cells.gate` and `category_mapping.gate`, adds a
    gate column and a gate token slot to the tables, and supports void and supplementary runs. All of this appears
    only when the manifest has a gate case. Any other kind is still refused.
- **K4, a null `judging_profile`** (`run.template.js`). Accepted only when the manifest has no review case. With a
  review case it is refused with its own reason. An absent key is still refused either way, and a filled profile
  still needs its qualification or the bootstrap line.
- **K6, docs.**
  - Kit README: a section "Run 4's case keys: category, mutants, gate", one paragraph per key plus one on the null
    judge. It includes the adapter note that the task object's `category` is what `rate` will read under

  - The `grade.sh`, observations and scores parts of the kit README are updated.
  - Pack-format README: the cases bullet, the category text, `cases.pin.mutants[]` and every `cases.gate.*` key.
  - One CHANGELOG line under Unreleased.

6. No `{pack}` placeholder in `commands.gate`. A gate command that runs a checker kept in the checkout can protect

## What went wrong and was fixed

- The first edit scripts were bash heredocs, which broke on quoting ("unexpected EOF"). They were moved to scratch
  files.
- The first gate-timeout test used a Python sleep, which risked an orphaned child on Windows. It now uses a bash busy
  loop with a 1 s timeout.
- The first draft of "green at the base fails" had a sub-case that actually passed. It was removed.
- The docs test wanted the bare key names. The README wrote them as `invariantsIntact: {path: bool}`, and was
  reworded.
- The full run caught a real regression, `SharedPack.test_the_manifest_carries_every_field_of_the_format`. That test
  requires the shared pack to carry every field the format README documents, and the shared pack carries neither
  mutants nor a gate case. The shared pack's manifest is outside this unit's paths, and a gate case is not its kind.
  The fix:
  - the test now checks `cases.pin.mutants*` and `cases.gate.*` on the kit fixtures' own shapes (`GATE_CASE`, the
    mutant list), with an assertion that the README still documents them;
  - the README names `mutants[].id` and `mutants[].commit` in full, as `cases.pin.mutants[].id` and
    `cases.pin.mutants[].commit`.
- Four guards that no test caught on the first pass were fixed by strengthening the tests, as described above.
