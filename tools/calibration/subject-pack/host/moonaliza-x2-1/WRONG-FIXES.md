The pin rows are the tests of `zz_accepted_x2_1.test.ts`: the twelve **journey rows** (first sign-in before commit 1,
sign-in before commit 3, refresh before commit 3, refresh before commit 4, each with EACCES, with EBUSY and with EIO at
the next three starts, the first ten years after the crash and each ten years after the one before, failing at the
stat, at the open and at the read), the **other-errno row** (the same four crash points, each with EPERM, EMFILE,
EINVAL and UNKNOWN at the next three starts, as in the journey rows, then a readable start), the
**tombstone row** (a sign-out whose removals failed, then an
unreadable start), the **orphan row** (a crash after staging, before the file write, then four unreadable starts in a row,
ten years apart, failing at the stat, the open, the read and the stat, then a readable one), the **signed-out orphan row** (a sign-out, then a sign-in that crashed after staging, before
the file write, then a readable start of a file that names no account), the **refused-file row** (the signed-out
orphan row's crash, then the file replaced by one the store reads and refuses: invalid JSON, over 64 KiB, or with an
extra key or with version 2, each in a start of its own), the **named refused-file row** (a crash after the file
named the new pair: a first sign-in's before commit 1 and, beside the old committed pair, a sign-in's or a
refresh's before commit 3 and a refresh's before commit 4; then that file replaced by one the store reads and refuses
in the same four ways, each in a start of its own), the **ENOENT row** (a first sign-in that crashed before any file
existed, and a sign-in that crashed after staging and a refresh that crashed before commit 3, each with its file then
removed beside the committed account), the
**app-changed row** (a file issued to another app, with an orphan
pair beside it), the **vault-default row** (the reconcile called with the references only) and the **unreadable-run row** (a
first sign-in that crashed before commit 1 and a refresh that crashed before commit 4, each followed by four starts in a
row that cannot read the file, with EACCES, EACCES again, EBUSY and EIO, failing at the stat, the open, the read and
the stat, each ten years after the one before, then a readable start), and four rows of review loop 9: the **lasting
row** (a first sign-in before commit 1, a sign-in before commit 3 and a refresh before commit 4, each followed by four
starts in a row that meet the same failure, code and call, as a lasting cause gives it: EACCES at the directory,
EACCES at the open and EIO at the read, ten years apart, then a readable start), the **engine row** (a first sign-in
before commit 1 and a refresh before commit 4, each beside a staged entry the engine names, then EACCES at the stat,
EBUSY at the open and EIO at the read at three starts in a row, then a readable start), the **tombstone-at-each-point
row** (the tombstone row's sign-out, then an unreadable start failing with EBUSY at the open, and one at the read) and
the **orphan-codes row** (the orphan row's crash, then for each of the seven codes three unreadable starts, at the
stat, the open and the read, then a readable one). Each later start runs with every clock it reads moved as far as
the test's, and the data directory's file times moved back as much.
